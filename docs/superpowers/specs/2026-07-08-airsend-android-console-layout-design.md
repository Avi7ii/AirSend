# AirSend Android 控制台布局设计

## 目标

把 Android 端从 InstallerX 信息架构改成 AirSend 自己的同步控制台。第一阶段先建立正确的页面结构和视觉语言，让打开应用后像 AirSend，而不是像安装器换皮。

主导航采用用户已确认的四栏：

- 首页
- 设备
- 活动
- 设置

活动页顶部增加 `发送 / 接收` 两个页内 tab。这个 tab 的视觉应照抄底部悬浮条的胶囊、圆角、选中态和液态玻璃/模糊风格，让页面内切换与主导航属于同一个 UI 系统。

## 范围

本次包含：

- 将底部主导航从 `首页 / 配置 / 历史 / 偏好` 改为 `首页 / 设备 / 活动 / 设置`。
- Material 与 Miuix 两套主壳都同步调整。
- 将主 pager 的四个页面替换为 AirSend 控制台页面壳。
- 首页展示 AirSend 同步健康概览：后台服务、LSPosed、守护进程、剪贴板同步、最近同步状态。
- 设备页展示 AirSend peers/设备管理入口：在线设备、Direct Share、重新发现、手动添加。
- 活动页展示顶部 `发送 / 接收` tab，并分别展示发送记录和接收记录区域。
- 设置页承载外观主题、启动/权限、日志、关于等入口。
- 保留现有 InstallerX/Miuix 视觉组件、液态玻璃悬浮底栏、主题系统和 KSU 风格主题设置入口。

本次不包含：

- 真实传输历史持久化。
- 完整 peers 数据仓库重构。
- 剪贴板正文历史展示。
- 新的网络协议或后台服务逻辑。
- macOS 端改动。

## 视觉复用原则

不得原创一套新 UI。

实现顺序必须是：

1. 能直接复用现有 InstallerX、Miuix 或 KSU 组件时，直接复用。
2. 现成组件只差内容或参数时，只改内容、参数、图标和状态，不重写视觉结构。
3. 组件无法直接复用时，按现有组件做像素级风格模仿，包括圆角、内边距、字号、选中态、模糊/玻璃效果、动画节奏和颜色来源。
4. 只允许为了 AirSend 信息架构重排页面内容，不允许发明新的视觉语言。

活动页顶部 `发送 / 接收` tab 必须优先复用底部悬浮条或其内部构件；如果底部悬浮条无法作为页内组件复用，则新组件也必须像素级模仿底部悬浮条风格。

## 页面设计

### 首页

首页负责回答“AirSend 现在能不能同步”。

首屏结构：

- 顶部大状态卡：显示 `AirSend 已就绪`、`正在保持后台同步` 或需要处理的状态。
- 状态小卡：后台服务、LSPosed 模块、守护进程、剪贴板同步。
- 最近同步：展示最近一条发送、接收或剪贴板事件；没有数据时显示空状态。
- 快捷操作：启动/重启同步服务、重新发现设备、打开 LSPosed。

第一阶段允许这些状态使用保守占位值和已有能力探测，不阻塞页面布局。

### 设备

设备页负责回答“我能发给谁”。

结构：

- 当前目标卡：当前默认发送目标或广播模式。
- 在线设备列表：Mac、手机等 peers。无数据时显示空状态。
- Direct Share 区域：提示系统分享入口会使用 AirSend 动态快捷方式。
- 操作区：重新扫描、手动添加 IP、广播模式。

### 活动

活动页负责回答“最近发生了什么”。

顶部加入页内 tab：

- `发送`
- `接收`

视觉要求：

- tab 容器优先复用底部悬浮条组件；无法复用时，像素级模仿底部悬浮条的圆角胶囊比例。
- 开启模糊/液态玻璃时，页内 tab 也使用同源的透明、模糊或玻璃质感。
- 选中态使用和底栏一致的指示器、强调色和动画节奏。
- 两个 tab 固定在活动页内容顶部，滚动内容从 tab 下方开始。

内容：

- 发送 tab：展示最近发送、分享目标、状态、失败原因。
- 接收 tab：展示最近接收、来源设备、状态、保存位置。
- 第一阶段无真实历史时显示高质量空状态，不展示假数据。

### 设置

设置页保留系统化配置入口，但去掉安装器语义。

主要分组：

- 外观：主题、Miuix/Material、Monet、强调色、色彩标准/风格、悬浮底栏、模糊。
- 同步：开机启动、后台服务、剪贴板同步。
- 权限：通知、媒体读取、LSPosed。
- 日志与诊断：导出日志、运行诊断。
- 关于：版本、开源许可。

## 架构

沿用当前 Compose 架构，不另起一套框架。

主要改动点：

- `Material3NavWrapper.kt`：主导航 tab 改为 AirSend 四栏。
- `MiuixNavWrapper.kt`：主导航 item 改为 AirSend 四栏。
- `SettingsPage.kt`：Material pager 内容换成 AirSend 四页。
- `MiuixSettingsPage.kt`：Miuix pager 内容换成 AirSend 四页。
- 新增或重命名页面组件：
  - `AirSendHomePage`
  - `AirSendDevicesPage`
  - `AirSendActivityPage`
  - `AirSendSettingsPage`
  - 对应 Miuix 版本可按现有目录风格命名。
- 新增页内 tab 组件，例如 `AirSendActivityTabBar`，视觉参数尽量复用 `FloatingBottomBar` 的尺寸、圆角、颜色与模糊模式。
- `AirSendActivityTabBar` 不做原创样式。优先包装 `FloatingBottomBar`/`FloatingBottomBarItem`；如果 API 不适合页内 tab，再复制其风格参数实现一个窄版页内组件。

保留现有主题状态流 `ThemeStateProvider` 和已有底栏设置。设置页中的外观入口继续走现有 `Route.Theme`。

## 数据流

第一阶段以 UI 壳和已有状态为主：

- 主题、底栏、模糊继续来自 `ThemeState`。
- 配置数量不再驱动主底栏 badge。
- AirSend 服务状态可先用简单可用性/占位状态表达。
- 活动页发送/接收列表先显示空状态，等待后续接入真实事件流。

后续数据层可以新增 `AirSendConsoleState`，统一承载服务、设备和活动数据。第一阶段不强行引入。

## 错误处理

- 没有设备时显示“未发现设备”，提供重新扫描入口。
- 没有活动时显示“暂无发送记录”或“暂无接收记录”。
- LSPosed 未启用时首页状态卡给出入口，但不阻断其他页面。
- 页面布局不得因为状态文本为空或过长而重叠。

## 测试

构建验证：

- 运行 Android debug 构建，确认 Compose 编译通过。

手动验证：

- 底栏为 `首页 / 设备 / 活动 / 设置`。
- Miuix 和 Material 模式都能进入四个页面。
- 活动页顶部出现 `发送 / 接收` tab。
- 活动页 tab 视觉与底部悬浮条一致，至少在圆角、选中态、间距和模糊方向上同源。
- 切换发送/接收不会影响底部主导航选中态。
- 文字在窄屏不溢出或重叠。

## 已批准决策

用户已选择同步控制台式布局，并明确要求活动页顶部增加 `发送 / 接收` 两个 tab，视觉照抄底部悬浮条。
